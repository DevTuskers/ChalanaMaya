# Security

This page describes what the ChalanaMaya server protects against and what it does not. It covers everything built in the [agent canvas plan](plans/agent-canvas.md) (phases 1a–6): the server shell, sessions, live sync, the MCP endpoint, media and animated components.

## Access: the session id is the key

There are no accounts. Anyone, person or agent, who has a board's id can read and change that board. Ids are 24 characters of random base64url (144 random bits), are never listed by the server and appear in logs only as their first 4 characters. Treat a board link like a password. Pages send `Referrer-Policy: strict-origin-when-cross-origin`, so other sites never see `/s/<id>`.

## Who can reach the server

- **Loopback by default.** `npm start` listens on `127.0.0.1` and `::1` only.
- **Host check.** Every request and socket upgrade must carry a `Host` that is `localhost`, `127.0.0.1`, `[::1]`, the host of `PUBLIC_URL`, or an `ALLOWED_HOSTS` entry (ports are ignored; IPv6 addresses are compared in bracketed, lower-case form). A `Host` must be exactly `host[:port]`: a value with a path, spaces, tabs or other characters is refused, and the page's CSP is built only from the normalised value, so `Host` cannot inject text into a header. Anything else gets 403 — as `{error: …}` JSON under `/api`, a JSON-RPC error under `/mcp`, and plain text for pages. This stops DNS-rebinding pages from talking to a local server.
- **Cross-site request guard.** Every request that changes something (`POST`, `PUT`, `PATCH`, `DELETE`, on any path, whatever its letter case or trailing slash) is refused with 403 when the browser marks it `Sec-Fetch-Site: cross-site` or sends an `Origin` other than the app's own address. Every such request except `/mcp` must also carry `X-ChalanaMaya: 1`, which a plain form or `text/plain` request from another site cannot add. `/mcp` is recognised the way the router matches it (`/MCP`, `/mcp/` included). `ALLOWED_ORIGINS` admits extra origins for `/mcp` only. Routes are matched case-sensitively and strictly, so `/API/...` reaches nothing. Socket upgrades with a foreign `Host` or `Origin` (or `Sec-Fetch-Site: cross-site`) are refused too.
- **Proxies.** `X-Forwarded-For` is ignored unless `TRUST_PROXY` is set, so a client cannot pick its own rate-limit bucket.
- **Rate limits** per address for board creation, uploads and `/mcp` (configurable, can be turned off).
- **MCP endpoint.** `/mcp` is stateless (no MCP sessions to hijack or expire), accepts only `POST` (405 otherwise) with JSON bodies up to 16 MB, and goes through the host check, the cross-site guard (browser pages need their origin in `ALLOWED_ORIGINS`) and its own rate limit. Every tool needs a board id and there is no tool or resource that lists boards, so an agent can only reach boards it was given. Tool input is converted and then strictly validated like every other write; tools never fetch other sites (media links are stored as links and only the browser loads them), and uploads are checked by magic bytes like the app's. The stdio bridge only forwards to `CHALANAMAYA_URL` and never opens the database.
- **Cloud agents and tunnels.** A cloud agent reaches the server only through a public HTTPS address (`PUBLIC_URL`). Then anyone who learns a board id can read and change that board, and anyone can create boards: there are no accounts. Share board links only with people and agents you trust, and stop the tunnel when you are done.

## What is stored

- Every item written to a board is checked by the same strict validator the app uses (`src/shared/validate.ts`): known types and fields only, colours, numbers, ids, links and lengths within limits. Anything else is refused with the field path, and nothing is stored. Board settings and file rows are checked the same way.
- Media uploads: PNG, JPEG, GIF, WebP, MP4 and WebM only, and the file's first bytes must match its claimed type (SVG and HTML are refused). Video size and duration are read from the MP4 or WebM header by a bounded parser; nothing is decoded on the server.
- Media links: only `https`, without user names or passwords, and not to IP addresses, `localhost`, single-word host names or private names (`.local`, `.internal`, `.lan`, `.home.arpa`, `.intranet`, `.corp`), names ending in a dot (`example.com.`) or wildcard IP names (`nip.io`, `sslip.io`, `xip.io`, `traefik.me`, `localtest.me`, `lvh.me`). This is a best-effort guard, not a network wall: a public name can still resolve to a private address, which is why the server never downloads links. The browser loads them in the live layer: pictures with `referrerpolicy="no-referrer"` (no `Referer` at all); videos follow the page's `Referrer-Policy: strict-origin-when-cross-origin`, because HTML gives `<video>` no `referrerpolicy` attribute, so a video site sees only the app's origin (for example `https://board.example.com/`), never the `/s/<id>` path. Either way the board address, which is its key, is never sent; they are never drawn into the board canvas (so it stays readable for the eyedropper and exports), and exports show a placeholder card with only the site name. If a canvas read still fails with a `SecurityError`, the eyedropper samples a media-free redraw. Files are stored by SHA-256 under `DATA_DIR/media` and served with `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; sandbox` and `Cross-Origin-Resource-Policy: same-origin`.
- Animated components: custom HTML and CSS (20 KB each) are checked on every write and file import (no scripts, event attributes, `javascript:` links, `@import`, non-`data:` `url()`, frames, objects, forms, links, meta, base, `foreignObject`, SVG animation elements (`<animate>`, `<animateTransform>`, `<animateMotion>`, `<set>`) or `<style>` in the HTML; event attributes are caught after a space or a `/`, as in `<img/onerror=…>`); refused content names the rule. In the browser the HTML is cleaned again with DOMPurify and the CSS filtered separately, then shown in `<iframe sandbox="">` (no scripts, a unique origin, no navigation, popups or forms) whose page starts with `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; img-src data:; font-src data:`, so a component can't run code, load anything or reach the board. The frame ignores the pointer and has a fixed light `color-scheme` that matches its page, so it stays see-through on the dark board. A `.chalana` file with an unsafe component still opens without that item, and the notice says so. Exports show a still card with the title, never the HTML.
- Deleting a board (`DELETE /api/sessions/:id`) removes it with its ops and every media file no other board uses, and closes its open sockets at once (code 4404). Boards never changed are removed after 24 hours.
- Size limits: 2 MiB per change batch, 12 MiB per import, 10 MiB per picture, 10 MiB per board (counted in UTF-8 bytes of the stored items), 5,000 items per board, plus the server-wide limits in the [setup guide](agents/setup.md#settings-environment-variables). Over a limit: 413 for a request, 507 when the server is full.

## The page

The app is served with a strict Content Security Policy: scripts only from the app itself, frames only from the supported web card providers (YouTube, Vimeo, Figma, CodePen), `connect-src` limited to the app and its own `ws://`/`wss://` address, `frame-ancestors 'none'`, `object-src 'none'`, `base-uri 'none'`. SVG export escapes every attribute value. (`npm run dev` relaxes the script rule for hot reload; never expose a dev server.)

## Exposing ChalanaMaya beyond your machine

Cloud agents cannot reach `localhost`. If you expose the server (tunnel, proxy, `HOST=0.0.0.0`), set `PUBLIC_URL` or `ALLOWED_HOSTS` and, behind a proxy, `TRUST_PROXY`. The session id is then the only protection for each board; prefer a short-lived tunnel and stop it when you are done. Traffic is only encrypted if your tunnel or proxy uses HTTPS.
